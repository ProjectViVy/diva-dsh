# dsh-see-now · v0.3.0-vivy-core · 验收

用户侧按顺序走；任一步失败先看第 7 条，不要把失败项写成通过。

1. **刷新**：硬刷新 `http://127.0.0.1:3082`（Ctrl+F5）。侧栏 `VIVY心核` 下应有「我看到了」；点它，主区显示「VIVY · 感知 / 我看到了」，不是空白、不是设置表单。
2. **设置分区已移除**：打开 DSH 设置，导航里**不再有**「看你看的东西」；原来那张表单现在在「我看到了 → 配置」里。若设置里仍出现，说明浏览器还在跑旧 bundle，先硬刷新。
3. **总览/会话**：总览四张卡（采集、悬浮窗、陪看会话、本次出图）+ 五个按钮；「会话」页有当前采集/当前循环与开始/结束按钮。`开始看` 后应出现「正在看」「陪看循环在跑」和一条「开始看：完成」；`停止` 后应回到「没在看」「无循环」。
4. **记录**：点「记录」，应看到时间/动作/结果/说明四列表格；至少应有刚才 start/stop 两条。文件路径应指向 `$DSH_HOME/see-now/lifecycle.jsonl`。记录只含动作，不含画面/标题。
5. **配置**：点「配置」，能读出当前转写服务与高级项；改一个值保存，重新读取应看到新值；再改回。
6. **隐私**：点「隐私」，应显示三条边界说明、`停止一切采集`、`关闭悬浮窗`、`清空动作记录` 和两个文件路径。清空会弹确认；确认后记录页只剩一条「清空记录」（审计动作本身），本步可跳过，避免清掉证据。
7. **真实出图**（本轮唯一硬缺口）：
   - 新会话里确认 `see_now` 工具存在；`see_now({action:"watch"})` 或 `/seenow` 跑一段**静止文档**和一段**视频/幻灯片**。
   - 记录每张图 token、CPU、端到端时延；模型描述必须说出只有画面上才有的信息。
   - 若开始后长时间 `0 帧`：先看 `runner.status().lastError`、ffmpeg 是否在 PATH、`see_now({action:"status"})`，不要先怀疑面板。
8. **失败排查**：
   - 侧栏没有「我看到了」：看浏览器控制台是否有 `loaded without registering "dsh-see-now"`；确认 `plugins/dsh-see-now/client.js` 是含 `SeeNowPanel` 的版本；`npm run setup:see-now`。
   - 面板报「没有这条路由：/lifecycle」：host 还是旧进程；`npm run stop` 后确认 3082 无监听，再 `npm start`（本次实测 `restart` 可能因控制台标题错误留下旧进程）。
   - 开始/停止报错：看面板顶部红条文案；服务端看 `~/.dsh/see-now/plugin-error.log` 或 host 日志。
9. **回滚**：`git -C plugins/dsh-see-now checkout -- .` 会清掉本地补丁（先 rename 备份），再 `npm run setup:see-now` 可重打；若要完全移除，按 `v0.2.0-install/acceptance.md` 第 7 条，先隔离再删。

**通过判据**：1–5 全过；7 至少跑通「静止 + 视频」两段，且模型描述能对上画面。6 的破坏性动作不要求执行。
