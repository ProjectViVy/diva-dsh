# dsh-see-now · v0.3.1-debug · 总结

- 目标：在「我看到了」里加一个调试窗口，点「开始看」几秒后就能看到宿主真实状态，方便判断抓屏到底有没有在跑、卡在哪。
- 做法：**第六个标签「调试」**，不新开独立窗口/进程。面板内每 1.5 秒轮询 `/api/see-now/lifecycle`；点「开始看」成功后自动切到调试页。
- 调试页显示：
  - 采集：在跑/停、源（screen/camera/video）、画质、帧数/出图数、队列、已运行/已停秒数。
  - 循环：唤醒次数、绑定的 session；窗口：pid、存活、心跳；听声音：在听/原因。
  - 最近错误（`lastError` / 窗口 reason / 循环 reason）与最近 6 条动作。
  - `<details>` 展开原始 `runner.status()` / loop / window / tuning JSON。
- 轮询只在「调试页打开」或「采集正在跑」时启动；停止且离开调试页就停，不做 24 小时后台轮询。
- 取舍：最简方案是复用现有 `/lifecycle` 状态，不新增服务端路由、不落盘新数据；备选是独立日志文件/SSE 推送，本轮不做——调试信息已经全在状态里，先别加管道。

## 验证

- 插件全量：**511 tests / 490 pass / 0 fail / 21 skipped**。
- 客户端接线：20/20 通过，新增「调试页在导航里」断言。
- 运行期：host 重启后（PID 32504，3082），面板出现「调试」；点「开始看」自动切到调试页；14 秒时读到 `源 screen`、`156 帧 / 0 张`、`已运行 14 秒`；点「停止」后读到「没在看」「采集收工」。
- `156 帧 / 0 张` 是**静止画面没有触发拼图**，不是抓屏失败；要验证出图仍需切到有变化的画面。
