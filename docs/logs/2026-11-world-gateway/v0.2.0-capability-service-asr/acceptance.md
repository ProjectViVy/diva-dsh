# v0.2.0 验收清单

重启（`npm run stop && npm start`）之后按顺序做，任何一步不对就停在那里看错误信息。

> **已验过什么**：三个套件（hub 13/13、引擎 8/8、面板标识 22/22）、隔离实例 3099 上一次完整
> 端到端（`catalog` 列出网关引擎 → `transcribe` 200 → 转写与原文一致，21.7 s）。
> **要你亲自看的**：重启后 3082 里的面板观感、麦克风到出文字这一段。

> **花钱的提醒**：识别请求真的会发到阿里云百炼，按音频时长计费。跑第 3 步之前先确认这是你想要的行为。

## 0. 前提（已就位，只需确认）

- `capability-hub` 的 `asr` 插槽**已启用**，模型 `qwen-audio-3.0-asr-flash`，
  `authRef` = `DASHSCOPE_API_KEY`（与 tts 共用）。
- 凭据已经填好；没填的话：面板 → 世界网关 → 语音合成 → 凭据，或语音页里填。

```powershell
# 浏览器控制台，不花钱
fetch('/dsh-capability-hub/api/resolve?capability=asr').then(r => r.json())
```

期望 `ok:true` 且带 `model:"qwen-audio-3.0-asr-flash"`。`ok:false, error:"not_enabled"` = 插槽没启用。

## 1. 语音页「识别」页

- [ ] 引擎下拉里有两个：`SenseVoiceSmall（本地）` 与 **`世界网关（千问）`**。
- [ ] 选「世界网关（千问）」后，选择框下面那行写清来源：「云端 · 音频会发给世界网关」，
      已就绪时后面跟「· 已就绪」，没就绪时跟「· 未就绪：<原因>」。
- [ ] 下面多一句提示：世界网关的模型/凭据/插槽开关在「世界网关」面板里。
- [ ] 「SenseVoice 参数」卡片顶部变成「这些参数只对『本机 SenseVoice』生效；当前用的是世界网关…」，
      而不再让人以为改了就影响识别。

## 2. 「总览」页

- [ ] 「语音识别」卡片：chip 里点名 `世界网关（千问） · 云端`，右侧「模型已就绪」。
- [ ] 「语音合成」卡片：显示「当前合成来源：世界网关语音包（云端 · 由世界网关转发到千问）」。
- [ ] **不再**出现「当前线路：本地合成」这种把网关线路写成本地合成的话。
- [ ] 「语音包」卡片里，`世界网关语音包` 挂「当前合成来源」角标，另外两个挂「未使用」。

## 3. 真识别（这一步花钱）

- [ ] 输入框左侧麦克风录一句「你好，我是 Diva。」→ 松手后应出文字，内容与你说的一致。
- [ ] 说一句更长的（5 秒以上）→ 仍然正确，耗时明显更长（十几秒量级，属正常）。
- [ ] 识别结果显示的来源标成世界网关，而不是本机 SenseVoice。

## 4. 失败路径（知道坏了会怎样，比知道好着更重要）

- [ ] 网关面板把 `asr` 插槽关掉 → 识别报「世界网关的 asr 插槽没启用」，码 `NOT_ENABLED`，
      **不会**偷偷改用本地引擎。
- [ ] 把凭据清空 → 报错里点名 `DASHSCOPE_API_KEY` 没填，且**不发**请求（不花钱）。
- [ ] 断网（或把 baseURL 改成不可达）→ 明确报连不上/失败，不会假装识别成功。
- [ ] 把引擎切回 `SenseVoiceSmall（本地）` → 老路径照旧可用，音频不出本机。
- [ ] 做完把插槽、凭据、引擎恢复原状。

## 已知不会发生的事（别当成 bug）

- 网关引擎**不准备模型**、没有下载进度条：它没有要下载的东西（面板应显示「无需准备」）。
- 它**没有本地进程**：`worker` 一栏是空的，「pid」这类信息不会出现。
- 识别慢（4 秒音频约 21 秒）是上游的现状，不是卡死；面板上超时之前会一直等。
- 切到网关引擎后，旧的 SenseVoice 缓存与审计仍在，只是这次识别不走它们。
