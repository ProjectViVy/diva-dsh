## 1. 网关自检（不花钱）

```powershell
# 在浏览器控制台里跑，或直接看面板「世界网关」页签
fetch('/dsh-capability-hub/api/resolve?capability=tts').then(r => r.json())
```

期望：`{"ok":true,"bindings":[{...model:"qwen3-tts-flash"...}]}`。
`ok:false, error:"not_enabled"` = 插槽没启用，回去做第 0 步。

      `http://127.0.0.1:3082/dsh-capability-hub/api`。

## 3. 真合成（这一步花钱，每次一分钱级）

- [ ] 点第三个包的「测试合成」→ 本地扬声器/播放器出声，内容「你好呀，语音包已经装好了。」。
- [ ] 点「生成试听」→ 同样出声。
- [ ] 把「要说的话」改成中文长句再试一次，时长明显变长（约 4 秒的量级）。

## 4. 失败路径（知道坏了会怎样，比知道好着更重要）

- [ ] 把网关地址改成 `http://127.0.0.1:1/dsh-capability-hub/api` 保存 → 试听应该报
      「连不上世界网关（宿主是否在运行？）」，而不是空白或假装成功。
- [ ] 在世界网关面板把 `tts` 插槽关掉 → 试听报「世界网关的 tts 插槽没启用」
      （码 `NOT_ENABLED`）。
- [ ] 把凭据清空 → 报错里明确指出缺 `DASHSCOPE_API_KEY`。
- [ ] 改完后把地址/插槽恢复。

## 5. 回归

- [ ] 切回「本地」线路，原来能用的本地合成仍然能用（如果本地包装着）。
- [ ] 切回「云端」线路，云端配置没被动过。
- [ ] 切到「世界网关」再切回来，两条老线路各自的音色草稿还在。

## 已知不会发生的事（别当成 bug）

- 点「停止」对世界网关包是空操作（它没有进程可停）。
- 「移除并保留备份」对这个包会给出一句明确的拒绝，并建议改用切换线路。
- 断网时它不会偷偷回退到本地包。
