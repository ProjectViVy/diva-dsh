## 改了什么（行为/结论变化，不是文件清单）

1. **定义收窄**：PENS 从「agent 的应用环境（可能含面板、状态）」收窄为**应用接线总线 + 接线清单**；明确它不做工作台、不做 OS、不做 agent 框架。
2. **「无记忆」的三条硬推论**（§10.2）：状态归应用 / 「做到哪」归 agent / 暴露权在宿主。
3. **最重要的一处修正**：此前把「安装≠激活≠暴露」整体算作 PENS 职责；收窄后**只有前两段归 PENS，第三段（上下文暴露）必须归宿主**，否则 PENS 就在做上下文管理，等于隐性记忆。
4. **接线抽象**（§10.3）：打开/附着 · 受限动作集 + 作业（job/进度/取消/超时）· 观察（读回自证）· 制品（路径 + 校验和）；并加一条不变量：PENS 持久化只允许句柄 / 权限账本 / 包元数据。
5. **Blender 解剖**（§10.4）：三路线对比（官方 Python API / 文件 CLI / GUI 自动化），结论是必须落在应用自己的脚本接口上；给出首个 PEN 的六项最小验收。
6. **跨 agent 最小面**（§10.5）：只标准化三样（MCP 调用形状 / manifest / 身份与租约），并写死不承诺「无人请求的主动唤醒」。
7. **关系重排**（§10.6）：四个轴（provider / PEN / 人格 / 记忆）各归其位，一条判据：记住「做到哪」归 agent，启动外部世界归 PENS。
8. **新风险 R7–R11** 与**新决策 D7–D9**（首个 PEN 选型、接口形状、暴露权归属）。

## 影响面

- 用户可见：无（纯文档）。
- 对既有决策的影响：D4 被 §10.6 钉死（provider 与 PEN 都不得携带人格与记忆）；D3 被 §10.2 推论 3 加强（暴露清单必须在宿主侧）。
- 重启要求：无。

## 未验证

1. Blender 脚本接口在目标版本（4.x / 5.x）上的具体 API 与后台渲染行为——**未在本机跑过任何 Blender**；
2. Codex / Hermes 各自对 MCP 的覆盖（tools / resources / progress / cancellation / 通知方向）——未测，只在 §10.5 给了矩阵模板；
3. 「租约」的冲突语义（两个 agent 抢一个实例）——只是设计建议，未实现、未验证；
4. 动作白名单的实际粒度（`bpy.ops.*` 里哪些算安全）——未枚举。
