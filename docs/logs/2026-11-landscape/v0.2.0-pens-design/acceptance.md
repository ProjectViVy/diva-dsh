# 验收步骤 v0.2.0 PENS 设计

> 用户视角：这份设计能不能直接开工，还是需要先改。

## 前置

打开 `docs/research/pens-design.md`。不需要任何进程。

## 步骤

1. 读 §0（9 条结论）
   - 预期：能一句话说清「4 个恒定工具 + 5 族适配器 + 每游戏一份 profile + 深度分级」
   - 实测：

2. 读 §3（接口）
   - 预期：4 个工具的签名与返回结构可以照着写代码；`act` 带 `expect`、长动作返回 job、观察带游标
   - 实测：

3. 读 §4（五族）与 §5（深度）
   - 预期：能判断「先做哪一族」；D0–D3 的判据可验收
   - 实测：

4. 读 §6 / §7（时间与观察压缩）
   - 预期：实时游戏「合帧不积压、超时即停、不可暂停只给 D0」三条能接受
   - 实测：

5. 读 §9（profile 示例）
   - 预期：一份 profile 20–60 行、纯数据，能被你自己照着写第二份
   - 实测：

6. 读 §10（分期）
   - 预期：M0 的验收是「两个 host 各玩 10 分钟」，范围不含商店/面板/反作弊
   - 实测：

7. 拍板
   - 预期：给出「M0 开工 / 先改某几处 / 暂不做」三选一
   - 实测：

## 不通过时怎么反馈

- 若认为「工具面恒定 4 个」太窄（比如需要更多宿主侧语义），指出缺哪个语义、为什么不能走 schema；
- 若认为「5 族」里的某一族不该做（例如 Mod 框架成本太高），直接删族，我重排分期；
- 若「尽可能多」的目标其实指「同一款游戏能玩很久」而不是「能玩很多款」，请明说——那会把设计重心从族覆盖移到单游戏深度，M0 要改。
