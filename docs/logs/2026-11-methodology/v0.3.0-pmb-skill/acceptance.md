# 验收步骤 v0.3.0

> 用户视角：新开一个会话，看它动手前的第一句话。

## 前置

新开一个 DSH 会话，cwd 在 `diva-dsh/` 根目录。

## 步骤

1. 让它做一件真的要改代码的小事（例如「把某个报错文案改清楚」）。
   - 预期：动手前先给「最简方案 + 一个备选 + 取舍依据」，且方案边界收在需求内（不顺手重构、不加没要求的配置）。
   - 实测：<待填>

2. 问它「开发前要读什么」。
   - 预期：答出 `TODOLIST.md` 的 `NOW` 与 `skills/more-faster-better-economical/SKILL.md` 两件，顺序是先状态、后原则。
   - 实测：<待填>

3. 让它审查一段改动。
   - 预期：findings 按影响排序，每条给「位置 + 证据 + 后果 + 最小修正」；没有可说「没有实质问题」，不硬凑。
   - 实测：<待填>

## 不通过时怎么反馈

指出它漏了哪一项（没读 / 读了没照做 / 照做但输出格式跑偏），我据此改 `AGENTS.md` 的措辞，不改 skill 原文。
