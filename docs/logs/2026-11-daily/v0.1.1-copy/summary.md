# 「日常」页面插件（dsh-daily）· v0.1.1-copy · 总结

- 目标：纠正 v0.1.0 的偏差 —— 那一版把参考原型「重新设计」成了 DIVA 风格的三视图，
  用户要的是**照搬原型内容**（文案/条目/数字/按钮一字不改），只把皮换成 DIVA 核心元素。
- 性质：重写 `client.js`（约 855 行，全部界面）+ 重写测试 + 文档同步。未改上游仓，未提交。
- 交付：
  1. `plugins/dsh-daily/client.js` —— 两栏工作台：左对话栏（品牌头、问候、今日清单卡、
     进行中任务卡、一问一答、待确认卡、邮件卡、步骤条、输入框），右上下文栏四页
     （Today 简报/身体信号/进行中/安排/待你确认/旅行/快速打开；任务 4 条 + 筛选；
     记忆 灵感 3 + 长期目标 3 + 本周观察 3；能力 快速打开 6 + 应用 5 + 设置 3 + 账户 4）。
  2. `tests/daily-client.test.mjs` —— 12 项：注册形状、两栏骨架、四页逐条文案、
     勾选/筛选/开关三个交互（假 React，无浏览器、无依赖）。
  3. `plugins/dsh-daily/README.md`、`docs/logs/2026-11-daily/v0.1.1-copy/`。
- 关键取舍：
  - **照搬优先于「再设计」**：内容段（`CHAT` / `TODAY` / `TASKS` / `MEMORY` / `SKILLS`）
    就是原型文字。判断标准从「看起来像 DIVA」改成「渲染出的文字能覆盖原型每一行」，
    所以验证手段也换成逐行比对（400+ 行全中），而不是看截图顺不顺眼。
  - **两栏而不是「一页三视图」**：原型的信息架构是对话 + 上下文双栏，任务/记忆/能力
    在右栏切页。v0.1.0 把它拍平成一页三视图，丢了对话这条主线。现在左栏常驻。
  - **只换皮**：颜色/圆角/阴影/渐变落进 `.dl{--dl-*}` 一段变量，不引用页面外的皮肤 token
    也成立；渐变只用于宝石标记、进度填充、开关打开态。
  - **图标手写**：一张 16px 描边图标集（`ICON`），不引第三方图标包，也不加构建步骤。
    第一版把元素写成 `{type:'svg', props:{…}}` 字面量，真 React 会判 `Element type is invalid`
    ——已改成 `React.createElement`（离线渲染抓到的，见 `verification.md`）。
  - **交互只留能自证的四处**：切页、勾选、任务筛选、开关。其余按钮保持视觉（原型也没行为）。
- 未验证：真 GUI 里的像素（面板地址要带 `?token=`，本轮仍拿不到；离线 Chrome 已截四页）；
  1440 以下的窄窗折行；非 diva 皮肤下的观感。
- 已知阻塞：左栏是否真的落在「插件」之上，取决于 `dsh-vivy-studio/sidebar-core.js` 的白名单，
  而那份脚本是**宿主启动时读进 index.html** 的 —— 需要一次 `npm run restart` 才生效。
  这一条我做不到：本会话的 agent 就跑在那个宿主进程里，重启等于自杀。见 `acceptance.md`。
- 下一步：用户 `npm run restart` + 硬刷新 → 左栏「插件」上方出现独立「日常」→ 按
  `acceptance.md` 走 1–5 步。
