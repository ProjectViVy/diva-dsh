# 迭代日志（docs/logs）

> 证据层：每个交付一条记录。状态在仓库根的 `TODOLIST.md`，这里只记「发生过什么、凭什么说做完了」。
> 规则来源：根 `AGENTS.md` §2 与 §5 的 `iteration-log-required`。

## 1. 目录与命名

- 主题目录：`docs/logs/<YYYY-MM-theme>/`，按月 + 主题，例如 `2026-11-memory-decay`。
- 版本目录：`<YYYY-MM-theme>/vX.Y.Z-slug/`，例如 `v0.7.24-decay-window`；没有版本概念的仓库用 `v0.0.1-slug`。
- 什么时候建：**有交付才建**。一次会话没有产出就不建目录，只在 `TODOLIST` 条目里写「本轮无交付」。
- 一个版本目录 = 一个可独立回滚的交付批次。三个不相关的改动不要塞进同一个目录。

## 2. 四件套

| 文件 | 必须回答 | 不合格 |
| --- | --- | --- |
| `summary.md` | 改了什么、影响面、未验证什么 | 「修复了一些问题」 |
| `verification.md` | 跑了什么命令、预期、实际输出；跑不了的原因 | 只写「测试通过」 |
| `release.md` | 怎么发、发给谁、要重启什么；不适用要写原因 | 空文件，或只有一个「无」 |
| `acceptance.md` | 用户视角怎么验：点哪、看什么 | 复述 `summary.md` |

## 3. `summary.md` 的前 6 行块

召回时只读这 6 行。字段固定、顺序固定：

```markdown
- 状态：已交付 / 部分交付 / 已回滚
- 范围：<改了哪些文件或模块，一句话>
- 验证：<命令 + 通过数>
- 未验证：<具体没做的验证；没有也要写「无」>
- 下一步：<关联的 DV 条目，或「无」>
- 回滚：<命令或操作>
```

## 4. 归档

- 条目 `done` 后：`TODOLIST` 删掉该条，`Archive Index` 加一行 `[YYYY-MM-DD 关闭 DV-xxx](docs/logs/archive/completed-YYYY-MM-DD-<id>.md)`。
- 归档文件只写：原条目全文、结论、交付日志目录路径、回滚方式。
- `blocked` / `waiting-user` 永远留在活跃区，不归档。

## 5. 不改写历史

- `verification.md`、`acceptance.md` 一旦用于交付就不再修改。要更正就新开版本目录，或在同目录加 `notes.md` 追加说明。
- 不为「让历史好看一点」回填或改写旧记录。

## 6. 与 TODOLIST 的双向链接

- 活跃条目必须有 `日志:` 字段，指向版本目录。
- 版本目录的 `summary.md`「下一步」必须写回关联的 `DV-` 编号（或「无」）。
- 硬约定：**没有日志目录的条目不许标 `done`**。

## 7. 模板

新目录从 [`_TEMPLATE/`](_TEMPLATE/) 复制四份文件再改名；模板里的占位符 `<>` 必须替换掉，不留空。
