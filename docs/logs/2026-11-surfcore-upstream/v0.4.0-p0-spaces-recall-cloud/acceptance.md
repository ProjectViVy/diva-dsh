# 验收步骤 v0.4.0

> 用户视角：点哪里、看什么、什么算通过。

## 前置

1. 重启实例加载新代码：`npm run stop && npm start`（本会话由运行中实例托管，未自行重启）。
2. 硬刷新 DSH 面板（`Ctrl+Shift+R`）。
3. 打开「记忆宫殿 → 设置」。

## 步骤

### A. 空间与迁移（不依赖 key）

1. 看「设置 → 向量空间」卡片
   - 预期：`活动空间 local-xenova-all-minilm-l6-v2@384`、`1 个空间`、表格里一行 `使用中`，`缺当前空间向量` 不出现
   - 实测：
2. 看「设置 → 诊断」
   - 预期：`来源 本地`；`召回 注入 0 次 / 兜底 0 次`
   - 实测：

### B. 本地召回

3. 在对话里问一件库里确实有的事（例如「还记得那次旅行吗」）
   - 预期：模型回答里出现与旧记忆一致的细节；`诊断` 的 `注入` 计数 +1
   - 实测：
4. 问一件库里没有的事
   - 预期：模型说记不清，不编造；注入计数可能 +1（块内可能为空列表则不加）
   - 实测：

### C. 云端探测（有 key 之后）

5. 世界网关面板 → 「向量化」插槽：启用、`kind=dashscope`、`baseURL` 填真实地址、模型填 `text-embedding-v4`、填入 `DASHSCOPE_API_KEY`
6. 记忆宫殿 → 设置 → 「向量来源」选「云端 / 世界网关」→ 点「探测向量接口」
   - 预期：绿色提示 `探测成功：dashscope / text-embedding-v4 返回 N 维，用时 Xms`
   - 实测：
7. 若 `N ≠ 云端向量维度`：把它改成 `N`，再探测一次
   - 预期：维度一致
   - 实测：
8. 保存设置
   - 预期：`向量空间` 卡片出现第二行 `cloud-dashscope-text-embedding-v4@N` 标 `使用中`；`缺当前空间向量` 显示旧记忆条数
   - 实测：
9. 点「重建缺失向量」
   - 预期：`重建完成：更新 K，失败 0`；再刷新后 `缺当前空间向量` 消失，两行空间各有向量数
   - 实测：
10. 再问一次第 3 步的问题
    - 预期：仍能召回（这次是云端向量命中）
    - 实测：

### D. 回滚

11. 「向量来源」改回「本地模型」→ 保存
    - 预期：活动空间回到 `local-…@384`，云端空间仍列为 `保留`，向量数不变，无需重建
    - 实测：

## 不通过时怎么反馈

把以下三项发回来：
1. 「设置 → 诊断」整块的截图（含错误码与建议）；
2. `node scripts/embedding-probe.mjs --json` 的输出（不含 key）；
3. `docs/logs/2026-11-surfcore-upstream/v0.4.0-p0-spaces-recall-cloud/verification.md` 里对应行号的实际结果。
