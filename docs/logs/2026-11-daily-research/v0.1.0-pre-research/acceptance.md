## 2. 拍板后的实施验收（按路线）

### A 只读面板（1–2 天）

- A1 `GET /orchestrator/api/overview` 与 `/tickets` 在 GUI 同源下 200，且带 `x-orchestrator-request: 1`；跨源访问 403。
- A2 Today 出现 ≥1 张真实卡片（来自 attention 或 tickets），数据可追溯到某条记录。
- A3 无数据/服务未启用时显示空态，不白屏、不弹错误弹窗。
- A4 刷新后卡片仍在（来自服务端记录而非组件 state）。

### B 第三方 Conversation View（3–5 天）

- B1 日常页只出现 user 与 assistant 文本 + 卡片；工具调用、diff、命令在 DOM 里不存在（不是 CSS 隐藏）。
- B2 流式增量正常；切页再回来不重复、不丢消息。
- B3 与内置 Chat 不打架：同一会话切换视图后状态一致，无双重 binding 报错。
- B4 刷新/重放后内容一致（不重复消费动作）。

### C `daily` Source（先不做）

- C1 四类消息（ack/answer/result/attention）各能在页面出现一次，且不重复。
- C2 断线重连后 Outbox 未发消息补齐一次、不补两次。

### 卡片层（无论走 A 还是 B）

- D1 13 块中至少 6 块可被 agent 生成并渲染；未知块降级为 `text` 不报错。
- D2 超限文档（>8KB / >24 块）被截断并提示，不白屏。
- D3 卡片视觉与纸墨一致（tone 映射），agent 无法指定颜色/字号。
- D4 `image.src` 只接受附件与白名单域名；越界渲染为占位。
