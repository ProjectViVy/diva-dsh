## 2. 拍板后的实施验收（按所选项）

### 若 D2 = B（受控卡片 schema）

- B1 同一份工具结果在「列表模式」与「卡片模式」下都能渲染，且卡片 props 校验失败时降级为文字，不白屏。
- B2 模型只能从白名单里选卡片名；给一个不存在的卡片名，工具返回可读错误且不出卡片。
- B3 卡片组件出现在 Web GUI（http://127.0.0.1:3082）刷新后仍在；会话重放后卡片恢复。
- B4 `npm run status` 正常、`npm test` 通过；改动只落在插件仓，`deepseek-harness/` 与 `plugins/surfcore/` 无 diff。

### 若 D2 = C（MCP Apps）

- C1 Web 客户端能加载一个最小 MCP App（`ui://` 资源），iframe 沙箱内渲染且不越权访问宿主。
- C2 A2UI-over-MCP 的示例 server 能在里面跑通一次 `updateComponents` + `action` 回流。
- C3 桌面端（Electron 壳）行为与 Web 一致，或明确不支持并在文档写明。
- C4 安全：iframe 的 CSP、postMessage 白名单、资源来源校验各有一条负向用例。

### 若 D2 = D（自建 A2UI 插件）

- D1 wire 消息能持久化并在会话重放后恢复；重放不重复消费动作。
- D2 `action` 回流成为一个新的用户输入，且不破坏既有 turn 生命周期（并发发消息、停止、重试各测一次）。
- D3 catalog 越界被拒，并给出可读错误。
