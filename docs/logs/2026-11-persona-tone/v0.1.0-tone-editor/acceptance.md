# acceptance — v0.1.0-tone-editor

前置：`npm run stop && npm start`（新增浏览器半册，必须重启），然后浏览器**硬刷新**（Ctrl+F5）。
本会话由运行中的实例托管，重启会终止当前回合，所以这一步留给面板空闲时做。

## A. 设置页改名

1. 打开 更多 → 设置。
2. 左侧导航里原来的「人格」应变成「**人格与语气**」；点开，页内标题也是「人格与语气」。
3. 「启用人格」开关与说明仍照旧可用。

## B. 语气块出现

4. 「人格与语气」页里，开关下方应出现「**语气**」卡片：
   - 右上角徽标「插件默认」（还没改过时）；
   - 编辑框里是「## 怎么跟人说话」到「语气随场合…」那一段中文；
   - 底部显示字符数与「留空保存 = 去掉语气小节，只保留编排器规则」。

## C. 保存

5. 把某一行的措辞改掉（例如把「先给结论，再给理由。」改成「先给结论，理由跟在后面。」），点「保存」。
6. 期望：卡片提示「已保存 · rN，下一轮请求生效…」，徽标变「已自定义」，字符数随文本变化。
7. 打开 Superagent 的 Settings → Prompts → Full prompt，`runtime/orchestrator`（中文）里应能看到改后的句子；History 里出现一个新版本，可一键回退。
8. 新开一轮对话，模型应读到你改后的语气规则（例如要求「先给结论」时，回答会先给结论）。

## D. 重启不丢

9. `npm run stop && npm start`，硬刷新，回到「人格与语气 → 语气」。
10. 期望：编辑框仍是你保存的文本，徽标仍是「已自定义」；Superagent 提示词不会多出新的版本（启动安装判定「已是本包文本」）。

## E. 恢复默认与留空

11. 点「恢复默认」：只把编辑框换回插件默认语气并提示「点保存写入」；此时不保存不应改动提示词。
12. 再点「保存」：提示词回到默认语气。
13. 清空编辑框后「保存」：提示词里的语气小节消失，只剩编排器规则；Superagent 的 Full prompt 里 `runtime/orchestrator` 从「你是本部署的编排器…」直接结束，没有「## 怎么跟人说话」。

## F. 失败与边界

14. 停掉 Superagent（或让它不可用）后保存：卡片显示「写入 Superagent 提示词失败…」与重试提示；本地 `tone.md` **不应**被改（重启后看到的还是上一次成功保存的文本）。
15. 在 Superagent 的 Prompts 面板里同时改动同一段再回来保存：应提示「Superagent 的提示词已被别处改动」；刷新后重试可成功。
16. 把 dsh-vivy-tone 停用（profile 里 `enabled: false`，重启）：语气卡片应显示「语气接口没有返回 JSON…」之类的可读错误，而不是空白；其余人格设置页功能不受影响。

## 已知限制

- 语气只覆盖「怎么跟人说话」这一段；其余 part 仍走 Superagent 的 Full prompt 面板。
- 如果曾经在 Superagent 面板里手改过 `runtime/orchestrator` 的开头部分（编排器规则），在这里保存会以「插件拼出的头 + 这里的语气」整段覆盖；Superagent 的提示词历史可回退。
