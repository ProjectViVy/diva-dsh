# SurfCore 功能核对与迁回

对照基准：`plugins/surfcore` 固定版本 v0.8.6；数据以 `.artifacts/backups/` 的迁移前快照为准。角色与桌宠不恢复；语音和记忆由独立插件管理。所有路径、依赖和运行状态应留在项目内；QQ、B站和语音引擎不自动启动。

> 2026-11-04 E2-S4：记忆面板已收敛为只读投影。下文提到的面板归档浏览、全量归档搜索、归档容量上限与 Markdown 导出阈值入口不再提供；后端归档读取、内部投递与回执仍保留。

## 本轮逐项核对

- 固定源码检查同时提示子模块已跟踪文件的本地修改；提交号仍作为基线，修改不会被覆盖，未跟踪构建产物不会触发提示。已用隔离 Git 仓库验证已暂存和未暂存的修改。
- 实际迁移前停止状态备份中，QQ 的 `alignment-brief.md` 和 B站的 `alignment-for-bili.md` 均为空；当前对应派生文件存在。该备份中的记忆配置字段和值也已在独立记忆配置中保留；此核对仅覆盖本工作区实际备份，不能代表其他安装的数据。
- 目的机制：节奏预设、最短／最长间隔、每日上限、安静时段、空闲时间、素材窗口和数量、失败重试、目标 QQ、状态和提示词预览已恢复；桌宠载体和角色状态按要求不恢复。
- 记忆规则：衰减卡上限、告警阈值、归档上限、两平台注入预算、清晰／模糊／遗忘周期、整理时间、自动压缩已恢复。QQ 私聊告警由独立记忆插件发起，默认关闭，显式开启后通过已运行的本地桥接发送；同一等级 12 小时冷却。
- SurfCore 打开时恢复记忆容量弹窗，每分钟读取独立记忆插件的状态；可立即压缩到 80%、直接打开记忆页、推迟两小时或确认当前级别。压缩及确认由独立插件执行，失败显示错误；记忆插件不可用时不阻塞 SurfCore。提醒范围与旧 SurfCore 面板一致，不是在其他侧栏页面常驻的全局提醒。
- 修正独立记忆状态接口的容量告警字段：已记录的最高提醒级别和确认级别也提供旧面板使用的顶层字段，确认后重启记忆服务仍可读回，避免相同级别反复弹窗。已用隔离记忆服务验证。
- 手动确认容量告警时恢复确认时间记录；未指定等级时沿用当前告警等级。手动操作更新卡片时间，压缩也更新最近整理时间；使用操作恢复记录中的同一时间，已通过隔离测试及全量回归验证。
- 使用独立测试数据贯通 SurfCore 提醒与真实记忆服务：达到阈值后确认提醒，重新打开面板时同一级别不再弹出。该测试模拟浏览器组件及 HTTP 边界，没有修改用户记忆；本机浏览器另已刷新并确认 SurfCore 页面加载，QQ 和 B站未运行。
- 记忆容量设为不限制时，容量提醒以配置的警告字数作为百分比基准和显示分母，避免显示成已使用字数除以零。
- 记忆规则数值保存后回显服务端实际接受的值；例如正数容量低于 2000 字时会显示引擎调整后的 2000。保存失败时保留输入并显示错误，已通过面板测试验证。
- 独立记忆面板曾补回衰减卡记录上限、管理员记忆保护阈值、全量归档记录告警上限和 Markdown 导出大小阈值；E2-S4 后只保留前两项，归档出站改为概览只读卡片。
- 记忆设置写入与提示词文件生成之间增加恢复记录；中断后读取记忆前先恢复输出，首次创建记忆卡时也可恢复。如果恢复前配置或记忆卡被外部更改，会停止并保留原文件。已用写入故障和重新创建服务验证；旧版本留下的不一致状态无法由该记录追溯。
- B站定时同步、容量告警及 QQ 同步设置在改写共享配置前会先完成待处理的记忆设置恢复；恢复失败则不写入新设置。已通过输出文件写入故障测试验证。
- 后台整理会先处理待恢复的设置，再检查记忆开关；因此关闭记忆时发生中断，重新启动后也能在后台完成恢复，不必先打开面板。已用隔离服务及写入故障验证。
- 记忆操作：手动记录的重要度、记忆范围、置顶、遗忘、整理、压缩至 80%、合并标题及置顶、初次相遇、全量搜索、衰减卡及全量卡原文预览和备份恢复均有入口。手动操作会记录脱敏后的恢复数据；若归档完成而卡片保存失败，后续访问会先恢复该操作并核对归档，卡片已保存时会重新生成派生输出。归档不完整或配置变化时停止恢复并保留现场。
- QQ→B站：公开群白名单、回看天数、消息数、字符上限、是否包含管理员、昵称、定时开关、手动同步、话题分类、群友近况、最近的梗、使用边界、摘要预览和数量审计已恢复。手动清空入口会先检查并占用桥接锁，将当前及轮转公开群记录、摘要移到项目内备份；对齐表和长期记忆卡不受影响。截断时保留使用边界，复用摘要时再次进行隐私检查。身份名称需单独开启，只使用明确确认的对齐记录；对齐文件修改后旧摘要失效。摘要组织方式与上游不完全相同。
- 修复公开群同步与记忆卡开关被错误绑定：记忆卡关闭时，单独启用并完成同步的公开群摘要仍进入 B站上下文；关闭公开群同步后立即撤销，记忆卡及 QQ 侧上下文仍遵守各自开关。已用隔离消息与预览测试验证，真实 B站投递尚待验证。
- 使用隔离公开群记录、真实独立记忆服务和本地 IPC 验证 QQ→B站上下文：白名单群消息可进入，其他群和私聊被排除，关闭同步会使桥接缓存中的旧摘要失效。未连接真实 QQ 或 B站。
- 公开群定期同步也独立于记忆卡开关；仍需分别开启公开群同步和定期同步并配置白名单，按设定间隔执行。已用隔离消息验证关闭记忆卡后的定时任务及关闭定期同步后的跳过行为。
- 同一轮后台检查先执行本地 QQ 公开群同步，再执行可能等待网络的 B站刷新；插件在两者之间停用时不会启动后一项。已模拟慢速 B站刷新验证执行顺序；若此前已有其他记忆操作占用串行队列，仍可能等待。
- 记忆卡关闭且没有待恢复设置时，即使记忆卡或旧归档损坏，独立公开群同步及 B站摘要预览仍可工作，不修改损坏文件；存在待恢复设置时上下文读取仍先执行恢复。已用损坏卡片及归档的隔离数据验证。
- 旧归档损坏时仍可修改或关闭公开群同步，并可在 QQ 桥接停止后将公开群记录移入备份；未完成的记忆设置恢复仍会阻止同步设置修改，避免覆盖共享配置。已用损坏归档及恢复写入故障验证。
- 已启用的公开群摘要损坏或无法读取时，设置面板仍可读取并关闭同步，显示错误并保留原摘要；实际上下文读取不会使用损坏摘要。已通过服务端与面板隔离测试验证。
- 旧全量归档损坏时仍可列出记忆卡备份、记录分享历史及查看和恢复分享历史备份；恢复分享历史仍要求 QQ 桥接停止。记忆卡恢复本身仍会先检查归档，归档损坏时不会继续恢复卡片。已用隔离损坏归档验证。
- B站公开记忆状态与简报预览读取独立 B站文件，不再被损坏的旧全量归档阻断；简报仍进行隐私复检，发布事务尚未结束时不展示未完成内容。已用隔离数据验证。
- B站定期刷新在进入串行队列后重新检查同步和记忆开关；若关闭操作先于排队刷新完成，刷新会跳过，不会再启动一次网络刷新。已通过暂停手动刷新、排队关闭和定期刷新验证；已开始的刷新不会被此开关中断。
