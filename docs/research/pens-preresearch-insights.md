## 0. 十二条洞察

| # | 洞察 | 后果 |
| --- | --- | --- |
| I-1 | 外部应用接线在现实里碎成**三种互不复用的形态**：引擎侧 MCP、壳 spawn 进程、页面自动化桥 | PENS 不是「第四种通道」，而是**把三者收敛成一个状态机** |
| I-2 | **视图层已被证明，能力层没被证明**：`SetParent`+静态服务能嵌窗口，但没人管「谁在用、能干什么、出错怎么办」 | PENS 只做能力层与状态，**不做视图** |
| I-3 | 有 API 的应用**已经被 MCP 覆盖**（Blender 32 工具、CUA 57、ComfyUI 39、剪映 8） | 适配器族的价值不在「再写一个 MCP」，而在**无 API 的应用**（模拟器/像素/UIA/游戏协议）→ 设计 §4 要重排 |
| I-4 | 这一层的**第一成本是 token**，不是延迟：全开 52.4k/轮，按需降到 ~9k | 「逐项开关」是最便宜的入口；观察压缩比适配器数量更重要 |
| I-5 | **生态里没人做过租约过期与抢占**：DSH 有 owner 围栏但无 TTL，Grok 无租约，Alife 的占用标记连 owner 都没有 | PENS 的差异化就在这八字段，**这是空白，不是抄写** |
| I-6 | 宿主契约**不由我们定**：命名、超时、指令上限、图像通道都被 MCP 桥写死，且 **MCP task 扩展未实现** | PENS 必须自带 job，不能借 MCP 原语 |
| I-7 | **「公开副本 ≠ 文档」是常态**：假配置（MCP 面板写不进去）、死 UI（本地模型只有注释）、热重载自相矛盾 | 预研纪律：任何「现成参照」必须实机验，「有面板」不等于「能跑」 |
| I-8 | 本仓已有三个外部进程，**各造各的轮子**（HTTP+token / stdio 子进程 / ffmpeg 安装器） | PENS 的进程模型应被本仓复用——**本仓是 PENS 的第一个 consumer，不是旁观者** |
| I-9 | 本机零外部应用 → M0 若坚持模拟器就卡死 | **M0 主链改 CDP 网页族**（零安装），Blender 作第二例 |
| I-10 | 数量 ≠ 秩序：9 个 MCP、16 个插件、44MB 文档，都没有换来「谁在控制这个实例」的答案 | PENS 卖的是**秩序**，不是覆盖数量 |
| I-11 | **工具面是协商结果，不是常量**：同一个 server，Codex 15 个、Claude 15 个（集合不同）、pi 14 个 | `pens_catalog` 必须按调用方声明的能力生成；「Blender 32 工具」只是上限参考 |
| I-12 | **Windows 上 `npx` 静默失败**：Codex 用 `npx` 零报错，模型只说「工具不存在」；换绝对 `node.exe` 即通 | 接线清单一律写绝对 `node` 路径，**禁止 `npx`**；core 必须常驻（`npx` 冷启 60.3s） |

## 2. I-1 / I-2：三种碎片，和一个没人占的位置

**观察到的三种形态**（淋雨家为样本，本仓同构）：

| 形态 | 谁在用 | 强在哪 | 缺什么 |
| --- | --- | --- | --- |
| 引擎侧 MCP | 9 个外部能力 | 工具面标准、跨模型通用 | 生命周期在引擎手里，壳只能写 `disabled` |
| 壳 spawn 进程 | Blender、工业软件 | 起停/探活/抓帧/嵌入全都能做 | 硬编码常量表，只服务一个壳，别的宿主复用不了 |
| 页面自动化桥 | 5 个网页 AI | 能操作没有 API 的东西 | claim 独占是土办法，无统一作业接口 |

**关键判断**：这三种形态各自都能跑，**加起来仍然回答不了三个问题**——谁在用这个实例？他能干什么？他崩溃了怎么办？

这就是 PENS 的位置：**不是再造一条通道，而是给三条通道套同一个状态机**（启动→就绪→运行→失败→关闭）+ 同一份租约 + 同一个作业接口。

**副产物**：既然视图层（`SetParent` + 本地静态服务 + `ResizeObserver` 同步几何）已经被证明可行，PENS 就不该碰渲染与布局；它只输出「帧 + 结构状态」，谁显示归壳。

## 3. I-3：适配器族的排序要改

设计 §4 列了六族：libretro / CDP / Mod / UIA / 像素 / 协议客户端。预研的发现让排序必须改：

| 族 | 现成覆盖情况 | 该不该在 M0 |
| --- | --- | --- |
| **有 API 的应用**（Blender/ComfyUI/剪映） | 已有成熟 MCP server（32/39/8 工具） | ❌ 不该是 M0 的「适配器」工作，而是「**复用现成 server + 补生命周期**」 |
| CDP 浏览器 | Playwright 生态第一 | ✅ **零安装，M0 主链** |
| 协议客户端（Minecraft） | Mineflayer 生态唯一 | ✅ 第二例（但需装游戏 + 账号） |
| 模拟器（libretro） | 需下载 + ROM 合法性 | ⚠ 推迟，但覆盖最广 |
| UIA / 像素 | 无现成标准，JS 绑定弱 | ⚠ 兜底族，最后做 |
| Mod（BepInEx/SMAPI） | 按游戏生态，版本绑定 | ⚠ 单游戏定制，不进 M0 |

**新洞察**：PENS 的差异化**不在「能接多少个应用」，而在「接上之后有没有秩序」**。所以「第 0 族 = 复用现成 MCP server」应写进设计，且它的实现成本接近零（一个 manifest + 一条 stdio 命令）。

## 4. I-4：token 是这层的第一成本

实测口径（与引擎 `token-meter` 同公式）：

```text
est = ceil(JSON.stringify(tools).length / 4) + 4
```

| 组合 | ≈token/轮 |
| --- | --- |
| 全开 9 项 | 52.4k（文档口径 58k） |
| 只开 CUA | 26.8k |
| 只开 Blender | 8.9k |
| 按需 1 项 + 5 个网页 AI | ~9k |

**推论**：
1. **一次接上 57 个工具 = 每轮烧 26.8k**，比任何一次观察都贵——所以 `pens_catalog` 必须能「按需拉 schema」（设计 §3 的方向被证实是对的）。
2. 观察压缩（summary/region/frame）不只是省 token，它是**决定「能不能玩 10 分钟」的唯一变量**：一局 200 次交互 × 每轮多 5k = 100 万 token。
3. 「逐项开关」是这层最便宜的入口，但它只是**安装态**的开关；真正要的是**会话级 × 动作级**（I-6 的空白）。

## 5. I-5：租约契约草案（本轮最重要的产出）

**生态扫描结论**：

| 实现 | owner | 能力档 | 过期 | 抢占 | 回收 |
| --- | --- | --- | --- | --- | --- |
| DSH jobs | ✅ `SessionId` 围栏 | ❌ | ❌ | ❌ | ✅ owner disposal |
| grok-build | 隐式（会话） | ✅ 四档 | ❌ | ❌ | 会话结束 |
| Alife | ❌（只有 reason） | ❌ | ❌ | ❌ | 调用方 Dispose |
| 本仓架构 | ✅ 唯一写者 | Policy 版本化 | ❌ | 部分（Ticket 串行） | 对账 |

→ **没有任何一个把「过期 + 抢占」做全**。这是 PENS 的真空白。

**八字段契约（建议进设计 §8）**：

```text
lease = {
  owner:       { agent_id, session_id, boot_epoch },   // 不只「谁」，还要「哪个进程的第几次启动」
  mode:        read | write | execute | admin,          // 借 Grok 四档，防止「有租约=什么都能干」
  scope:       实例 id + 资源子树,                        // 表达「我改材质、你改灯光」
  depth:       委托深度 + 来源链,                         // 主子争抢时的优先级依据
  expires:     绝对到期（单调时钟）,                      // 唯一裁决；忘了释放不能变成永久占用
  renewable:   可否续、续租带 owner+epoch,                // 长渲染不被自己的 TTL 误杀，僵尸不能续租永生
  preemptible: human > interactive > background,        // 人接管不必干等 TTL
  audit:       租约 id、前持有者、动作、结果、对账状态
}
```

**三条硬判据**：
1. **TTL 是唯一裁决**；心跳只用于续租，存活探测只用于「提前回收」（跨容器/远程 PID 不可信）。
2. **抢占走三步**：请求 → 让出确认 → 转移；**人类在场永不被打断**，只能请求。
3. **审计粒度**：破坏性动作逐条、读操作按轮聚合（防日志洪水，又答得出「谁读到了什么」）。

**明确不学**：Grok 的 fail-open（权限门必须 fail-closed）、Alife 的占用标记（无 owner 无 TTL）、把进程内状态当唯一真相、会话级单一 permission mode、让 agent 自批。

## 6. I-6：宿主契约是既成事实（含实测）

### 6.1 四宿主端到端实测矩阵（2026-11-12，Win11 / Node v24.14.1）

服务端统一为仓内 devDependency 的 `@modelcontextprotocol/server-everything` 2.0.0（绝对 `node` 入口），四家用**临时配置目录**隔离，未触碰用户真实配置。

| 宿主 | 版本 | 连接方式 | 初始化 | 工具数 | 调用 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| **Codex** | 0.167.0 | `CODEX_HOME=<tmp>; codex mcp add everything -- node <entry>` | ✅ `2025-06-18` | **15** | ✅ **调通**（3 次成功 2 次，1 次启动竞态） | rollout `mcp_tool_call` → `Echo: pens-codex-wire` |
| Claude Code | 2.1.216 | `CLAUDE_CONFIG_DIR=<tmp>; claude mcp add -s local …` | ✅ `2025-11-25` | 15 | ⚠ 未验证（`401 Invalid token`，既有凭证失效） | `claude mcp list` → ✔ Connected；wire `tools/list` 15 项 |
| pi | 0.80.7 | `PI_CODING_AGENT_DIR=<tmp>` + `--extension pi-mcp-extension` | ✅ `2025-11-25` | **14** | ⚠ 未验证（`invalid_api_key`，既有 key 失效） | wire `initialize`→`tools/list`；`[pi-mcp] Roots updated: 1` |
| DSH | rc.5 | 仓内 e2e 真实 stdio | ✅ | （断言 echo/get-sum/get-tiny-image） | ✅ 测试内真实调用 | `vitest e2e mcp-client` → `Tests 4 passed` |

**结论**：**能连 4/4，能调通且有证据 1/4（Codex）**；Claude/pi 卡在凭证而非协议。「MCP 是 3/4 原生」需修正为：**原生客户端 3/4（Codex/Claude/DSH），pi 需装官方扩展**。

### 6.2 新发现：工具面是协商结果，不是常量

同一个 server、同一个版本：

| 客户端声明能力 | 拿到的工具数 |
| --- | --- |
| Codex（elicitation form+url） | 15 |
| Claude（elicitation 空对象） | 15，但**集合不同** |
| pi（仅 roots） | **14**（无 elicitation 工具） |

→ **「接上这个应用有 N 个工具」是错的说法**；正确的是「在某个客户端上、声明了某些能力时，有 N 个工具」。这对 PENS 有两层后果：
1. `pens_catalog` 不能返回固定工具表，必须**按调用方声明的能力**生成；
2. 文档里写「Blender 32 工具」只能当上限参考，不同宿主会少几个。

### 6.3 三个必须顺着走的工程事实

| 事实 | 实测 | 后果 |
| --- | --- | --- |
| **Windows 上 `npx` 会静默失败** | Codex + `npx` 零报错，模型只说「工具不存在」（实为 spawn 不了 `npx.cmd`）；换绝对 `node.exe` 即通 | 接线清单**禁止写 `npx`**，一律绝对 `node` 路径 |
| 冷启动极慢 | 直连 node `initialize` 235ms；`npx -y` 冷启 **60.3s** / 热 1.72s | core 必须常驻（§16.8 自举的价值），不能每次靠 `npx` |
| 客户端只发 `initialize` + `tools/list` | 三家全程未发 `resources/list`、`prompts/list`；DSH 明确 prompts 不支持 | **别指望 resources/prompts 当主通道**；schema 拉取必须走工具参数或自建 HTTP |
| pi 扩展很贵 | 拉 212 包、耗时 11 分钟；无需构建（`.ts` 直载），但需 `mcp.json` + `lifecycle: eager` | 安装器要预置配置，并把下载计入首启 |

### 6.4 DSH MCP 桥的四项硬约束（读码）

| 约束 | 值 | 后果 |
| --- | --- | --- |
| 工具命名 | `mcp__<server>__<raw>`（与 Claude Code/Codex 同形） | 跨宿主天然一致，不必自造命名 |
| 单次调用超时 | 60s | 渲染/模拟必须走 job |
| 服务器指令 | ≤32KB，超限拒连 | 说明文本必须精简（这直接约束 AGENTS.fragment 的长度） |
| **MCP task 扩展** | **未实现** | **PENS 不能依赖长期任务原语，只能自带 job + 轮询** |
| 空 scope | 不产生任何工具与提示词 | D9 暴露权归宿主的最便宜落地口 |
| 环境清洗 | 子进程丢弃 `*KEY*/PASSWORD/SECRET/TOKEN`、`DSH_*` | MCP 壳不继承凭据 → 凭据引用必须走 PENS 自己的授权 |

### 6.5 验收要分两级

| 级别 | 判据 | 是否需要登录 | 能否 CI |
| --- | --- | --- | --- |
| **连接验收** | `initialize` + `tools/list` 成功 | 否 | ✅ |
| **调用验收** | `tools/call` 有一次真实回包 | 是 | ❌ |

→ 本次 Claude/pi 只能算连接验收通过；**报告里不得写成「四家全部通过」**。

## 7. I-7：调研纪律（本轮最大的方法论收获）

三个「文档说有、代码没有」的实例：

| 现象 | 证据 | 教训 |
| --- | --- | --- |
| MCP 面板写的是 `<工作台>` 占位，`parse` 得空集，9 行全显示「已开启」 | `mcp-panel.js:8,96-105,144` | **有 UI ≠ 能用** |
| `patchReload=live` 只有一行注释，仓库文档反说「必须重启」 | `mcp-panel.js:4-5` vs `配置片段.md:35` | **注释不是契约** |
| 本地模型面板存在，preload 只有注释，点击报「还没有通道」 | `preload.js:100-102`；`renderers.js:7078` | **占位 UI 会骗人** |

→ 建议进 AGENTS 的调研纪律：**「现成参照」必须实机验；不能跑的写「仅文档」，不写「已实现」**。这条也正好对应待拍 D5（反例验收）。

## 11. 一句话总结

> 这两年工作台把「接得上」做完了，把「谁在控制」留空了。
> PENS 不是再接一百个应用，而是给已经接上的那些装一个**有主的、会过期的、能审计**的把手。
